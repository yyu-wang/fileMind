## 2. 打包流程

### 2.1 命令入口

```bash
# 1. 在仓库根运行（bootstrap.sh 创建的 venv 必须已就绪，见 .venv/bin/python）
bash scripts/build-sidecar.sh --target aarch64-apple-darwin
bash scripts/build-sidecar.sh --target x86_64-apple-darwin   # Intel mac（Rosetta 2 或 x86 Python 环境）
bash scripts/build-sidecar.sh --target x86_64-pc-windows-msvc  # CI: Linux 交叉 + cargo-xwin 对应
bash scripts/build-sidecar.sh --target x86_64-unknown-linux-gnu
```

`--target` 参数影响：

- 产物名：`filemind-sidecar-{triple}`（Windows 自动加 `.exe`）
- PyInstaller EXE target_arch：通过环境变量 `PYINSTALLER_TARGET_ARCH` 由 spec 读入（PyInstaller 6.x `.spec` 模式不支持 CLI `--target-arch`）
- **注意**：macOS 跨 arch 打包需要目标架构的 Python 解释器；若同解释器仅能打包当前 arch

### 2.2 build-sidecar.sh 步骤

1. **解析 target triple**：`aarch64-apple-darwin` → `ARCH_PYI=arm64`、`BIN_SUFFIX` 空（macOS）/`.exe`（Win）
2. **环境校验**：venv python3 存在、venv 中 `pyinstaller --version` 可用
3. **清理**：`python-sidecar/build/` 与 `dist/` 彻底删除（PyInstaller 增量缓存在 `.cache/pyinstaller/`，非工作目录）
4. **PyInstaller**：
   - `PYINSTALLER_RUNTIME=1` 让 sidecar_entry / lifespan 知道走打包态分支
   - `PYINSTALLER_CONFIG_DIR=python-sidecar/.cache/pyinstaller` 避免 `~/Library/Application Support/pyinstaller` 权限问题
   - `--clean --noconfirm filemind-sidecar.spec`
5. **产物断言**：体积 `< 80MB`，超阈值 exit 5（附体积优化建议）
6. **复制 + 软链接**：
   - `dist/filemind-sidecar` → `filemind/binaries/filemind-sidecar-{triple}`
   - `filemind/binaries/filemind-sidecar` → `filemind-sidecar-{triple}`（当前 arch 默认路径，manager.rs 兜底）
7. **sha256 + T1.2 构建报告** stdout 输出

## 3. filemind-sidecar.spec 体积优化清单

| 措施                                                                                                                                                                    | 作用                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `excludes` 大模块清单：`lancedb.*`、`jieba.*`、`numpy.{fft,linalg,polynomial,ma,random,matrixlib,testing,distutils,distutils.tests,core.tests,lib.tests,compat,doc}` 等 | 去掉阶段 1 功能没用上的重组件，预计省 40~60MB                                                 |
| `optimize=2`（`python -OO` 字节码级别）                                                                                                                                 | 去掉 docstrings + assert，字节码体积 -10~15%                                                  |
| `strip=True`                                                                                                                                                            | 剥离原生 `.so` / Mach-O / PE 调试符号                                                         |
| `noarchive=False`（默认，使用 PYZ 归档）                                                                                                                                | 源码以 zip 嵌入 pkg 压缩；若 T1.3+ 启动慢可改 `True`（展开目录式）                            |
| `upx=False`（当前关闭）                                                                                                                                                 | 兼容性优先；若后续超 80MB 可开启（macOS 可能因 codesign/altool 拒绝 UPX 过的 Mach-O，需评估） |

**实测**：aarch64-apple-darwin onefile = 23.4MB（1 worker uvicorn + fastapi + httpx + psutil + pydantic v2 + starlette），预期后续加 lancedb/jieba 懒加载后仍 ≤ 60MB。

## 4. 入口与 PSK 注入流程（打包态 vs dev 态）

```
打包 onefile 启动：
  [进程 exec] filemind-sidecar
    → sidecar_entry.main()
      → _resolve_port()   → 读 SIDECAR_PORT env，默认 8765
      → _inject_psk()
           [1] PSK_HEX / FILEMIND_PSK env?
               Yes → bytes.fromhex() 写 state.psk
               No  → [2] stdin isatty()?
                          PIPE → 首行 hex 写 state.psk
                          TTY  → None (dev skip)
      → uvicorn.run("app.main:app", host=127.0.0.1, port=port, workers=1, ...)
           → app lifespan:
                (PYINSTALLER_RUNTIME=1 and state.psk 已存在) → 跳过 stdin 二次读

dev 模式启动（python -m uvicorn app.main:app 或 Rust 直接调 python）：
  → app lifespan:
       PSK 未注入 → 走 stdin PIPE 首行写 state.psk
```

**关键约束**：

- 打包态 **不再通过 stdin 读 PSK**（onefile bootloader 会复用 PIPE，二次 readline 阻塞），改由 sidecar_entry 在启动 uvicorn **之前**就通过环境变量写好 state.psk。lifespan 再看到 `psk is not None` 就跳过 stdin 分支。
- 打包态 PSK 支持两变量名：`PSK_HEX`（规范名）或 `FILEMIND_PSK`（项目命名空间别名），`PSK_HEX` 优先，`or` 回退。
- Go/No-Go `--binary` 模式用 `FILEMIND_PSK` 注入，与 CI 后续集成一致。

## 5. 跨架构 target triple

| 平台                | triple（`--target` 参数）  | ARCH_PYI | 产物后缀 |
| ------------------- | -------------------------- | -------- | -------- |
| macOS Apple Silicon | `aarch64-apple-darwin`     | `arm64`  | -        |
| macOS Intel         | `x86_64-apple-darwin`      | `x86_64` | -        |
| Windows x64         | `x86_64-pc-windows-msvc`   | `x86_64` | `.exe`   |
| Linux x64 glibc     | `x86_64-unknown-linux-gnu` | `x86_64` | -        |

默认软链接：`filemind/binaries/filemind-sidecar` → `filemind-sidecar-{当前build triple}`（供 `manager.rs start()` 默认路径兜底）。
